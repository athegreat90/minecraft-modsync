# Implementation report

This is a reviewable initial implementation, **not a verified production-quality MVP**. Runtime release gates remain open because shell DNS and Docker daemon access are unavailable in the current sandbox. No remote repository, PR, image or release has been published.

1. **Repository:** one local monorepo at `minecraft-modsync`, canonical `master`, implementation branch `feature/distributed-mvp`. The neighboring `olp-server` is untouched. See [repository strategy](REPOSITORY_STRATEGY.md).
2. **Components:** ten modules separate domain, protocol, scanner, resolver, Modrinth integration, agent, client, optional TUI, backend and fixtures. See [architecture](ARCHITECTURE.md).
3. **Host A deployment:** build/extract the independent agent; mount actual Crafty storage read-only, configure its protected state and mapping aliases, enroll and assign logical servers, then run scans. [Instructions](docker/agent/README.md).
4. **Host B deployment:** provision protected secret files and persistent MariaDB volume, deploy the backend stack and a trusted HTTPS proxy, bootstrap administrator login. [Instructions](docker/server/README.md).
5. **Host C installation:** build a JVM distribution or obtain a future verified native release; configure HTTPS, verify control-plane UUID, login, register an instance, plan/apply/verify. No Docker or resident service is required. [Usage](README.md).
6. **Connection/authentication:** agents and clients independently initiate HTTPS to B; enrollment yields an agent credential, local account login yields device access/refresh credentials. Database stores credential hashes. Assignments fence stale agents. These flows have source/tests but have not executed here. [Protocol](DISTRIBUTED_ARCHITECTURE.md).
7. **Networks:** configured stable DNS supports LAN, internal CA, VPN DNS and public HTTPS proxy deployments. No direct A-C path, inbound agent API, client database connection or cross-host bind mount exists. [Networking](NETWORKING.md).
8. **Migration:** explicit assignment transfer for A, consistent database restore and fenced DNS cutover for B, new device registration/profile retrieval for C. [Procedures](HOST_MIGRATION.md).
9. **Backup/recovery:** checksum-verified export/import scripts use MariaDB utilities and protected option files. Script transport/escaping tests passed against fakes; a real database restoration drill is unexecuted. [Database guide](DATABASE.md).
10. **Performance:** no native, resident-agent, memory, CPU, throughput or synchronization measurements exist. A benchmark harness reports process startup/file size and explicitly leaves other fields unmeasured. [Evidence policy](CLIENT_PERFORMANCE.md).
11. **Release behavior:** workflow definitions reconcile reachable master commits, build exact revisions, validate platforms/security and finalize deterministic prereleases only after success. They require explicit repository configuration and have not run. [Release guide](RELEASES.md).
12. **Images/artifacts:** Dockerfiles target independently packaged server/agent multi-architecture images; workflows define three native client platforms and agent/JVM artifacts. No built or published digest/binary is claimed.
13. **Executed checks:** seven Python tests passed (four release reconciliation, three fake backup transport); module/deployment boundary checks, Python compilation, shell syntax, Markdown local links and both production Compose configuration checks passed. The Java health probe compiled for Java 25. `./gradlew check` failed before download due to DNS; Docker execution was denied.
14. **Security:** implemented TLS verification, identity checks, Argon2id, revocation/rotation, role authorization, assignment generations, request/rate limits, audit correlation, read-only mounts, safe filenames, official-CDN constraints and SHA-512/CRC verification. Runtime security testing remains open. [Threat model](SECURITY.md).
15. **Limitations:** no official wrapper JAR, resolved dependency verification/locks, live OpenAPI contract verification, measured native workflows, complete Windows ACL handling, Crafty API adapter, persistent hash/catalog cache or retention policy. Missing dependency pins block rather than guess. See [MEMORY.md](MEMORY.md).
16. **Next work:** execute/fix Kotlin builds on an authorized JDK 25/Docker runner; run MariaDB/TLS/restoration/native/security tests; collect representative benchmarks; pin verified supply-chain artifacts; then configure an approved remote and prepare a real PR/release. The [MVP checklist](docs/deployment/MVP_CHECKLIST.md) intentionally remains unchecked pending evidence.
